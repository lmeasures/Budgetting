# ADR-008: Deployment and Infrastructure

## Status
Proposed

## Context
A deployment and infrastructure strategy must be defined covering:
- Frontend hosting and distribution
- Backend API deployment and scaling
- Database provisioning and backups
- Environment management (dev, staging, production)
- CI/CD pipeline automation
- Monitoring, logging, and error tracking
- Cost optimization

## Decision

### Deployment Architecture

```
Frontend (React)      Backend (Express)      Database (MongoDB)
├─ Vercel CDN         ├─ Container (Docker)  ├─ MongoDB Atlas
├─ Auto-scaling       ├─ AWS Lambda/ECS      ├─ Backups enabled
└─ Git-driven deploys └─ Serverless or VPS   └─ Encryption at rest
```

#### 1. Frontend Deployment

**Platform**: Vercel (Next.js/React optimized)

**Configuration**:
- **Source**: GitHub repository with automatic deployments
- **Environments**:
  - `production` → main branch
  - `staging` → develop branch
  - `preview` → feature branches (auto-generated URLs)
- **Build**:
  - React TypeScript compilation
  - Vite bundling with tree-shaking
  - Code splitting for lazy-loaded routes
- **CDN**: Vercel global CDN with edge caching
- **SSL**: Automatic HTTPS with Let's Encrypt renewal

**Deployment Pipeline**:
```
Git Push → GitHub → Vercel Build → Run Tests → Deploy → CDN Cache Purge
```

**Cost**: Free tier for hobby projects; $20+/month for production

#### 2. Backend API Deployment

**Platform Options** (recommend Vercel Functions initially, migrate to AWS Lambda at scale):

**Option A: Vercel Functions (Recommended for MVP)**
- Zero-friction deployment
- Same Git-driven workflow as frontend
- Scales automatically
- Cold start ~ 1-2s (acceptable for this workload)
- Cost: $0.50/1M invocations + data transfer

**Option B: AWS ECS with Fargate (Recommended for scale)**
- More control; warm containers
- Load balancing and auto-scaling policies
- Better for sustained traffic
- Cost: ~$30-50/month minimum

**Configuration** (Vercel Functions):
- Docker containerized Express API
- Environment variables via Vercel secrets
- Timeout: 30 seconds (standard)
- Memory: 512MB (Express + MongoDB driver)

**CI/CD Pipeline**:
```
Git Push → GitHub Actions → Run Tests → Build Docker → Vercel Deploy → Health Check
```

#### 3. Database Deployment

**MongoDB Atlas Configuration**:

| Environment | Tier | Region | Backup | Auto-Scaling |
|---|---|---|---|---|
| Development | Free | US-East | Manual | No |
| Staging | Shared ($57/mo) | US-East | Daily | No |
| Production | Flex or Dedicated | Multi-region | Hourly + PITR | Yes |

**Configuration Details**:
- **Network Access**: IP whitelist (Vercel IPs + VPN for admins)
- **Encryption**: TLS 1.2+ for transit; encryption at rest enabled
- **Backups**: Automated daily + point-in-time recovery (7-day retention)
- **Monitoring**: Atlas monitoring + CloudWatch integration
- **Replicas**: 3-node replica set (production only) for high availability

**Cost**: Free tier for dev; $57/mo staging; $150-300/mo production

#### 4. Environment Management

**Three Environments**:

| Aspect | Development | Staging | Production |
|---|---|---|---|
| Frontend URL | localhost:3000 | staging.budgetting.app | budgetting.app |
| Backend URL | localhost:3001 | api-staging.budgetting.app | api.budgetting.app |
| Database | MongoDB local or Atlas Free | Atlas Shared | Atlas Flex/Dedicated |
| Data Retention | 7 days | 30 days | Indefinite |
| Monitoring | Local logs | CloudWatch | CloudWatch + DataDog |

**Configuration Management**:
- `.env.local` (git-ignored, development only)
- `.env.staging` (GitHub Secrets)
- `.env.production` (GitHub Secrets, encrypted)
- Vercel Environment Variables (synced from GitHub Secrets)

#### 5. CI/CD Pipeline

**Tool**: GitHub Actions

**Workflow Stages**:

```
┌─ Trigger: Push to branch
│
├─ Stage 1: Install Dependencies
│  └─ npm ci
│
├─ Stage 2: Lint & Format
│  ├─ ESLint
│  ├─ Prettier
│  └─ TypeScript strict mode
│
├─ Stage 3: Run Tests
│  ├─ Unit tests (Jest)
│  ├─ Integration tests
│  └─ Coverage threshold: 70%
│
├─ Stage 4: Build
│  ├─ React build
│  ├─ Express bundle
│  └─ Docker image build (if applicable)
│
├─ Stage 5: Security Scan
│  ├─ npm audit
│  ├─ SAST (CodeQL)
│  └─ Dependency check
│
├─ Stage 6: Deploy (conditional on branch)
│  ├─ main branch → Production
│  ├─ develop branch → Staging
│  └─ feature/* → Preview
│
└─ Stage 7: Post-Deploy
   ├─ Smoke tests
   ├─ Health checks
   └─ Performance benchmarks
```

**YAML Configuration**: See `.github/workflows/deploy.yml` (to be created)

#### 6. Monitoring & Observability

**Error Tracking**: Sentry
- Captures frontend + backend errors
- Sourcemap support for debugging
- Alert on error threshold (10 errors/min)
- Cost: Free tier or $25/mo

**Logging**: Vercel native logs + CloudWatch
- Vercel captures stdout/stderr automatically
- MongoDB Atlas logs in CloudWatch
- Structured JSON logging from Express

**Uptime Monitoring**: Uptime Robot (free tier)
- Monitor API health endpoint every 5 minutes
- Alert on downtime

**Performance**: Vercel Analytics
- Web Vitals (LCP, CLS, FID)
- Real User Monitoring (RUM)

**Metrics Dashboard**: DataDog (optional, production only)
- API response times
- Database query latency
- User session heatmaps

#### 7. Cost Optimization

| Component | Monthly Estimate | Notes |
|---|---|---|
| Frontend (Vercel) | $0-20 | Scales with traffic |
| Backend (Vercel Functions) | $10-50 | Pay-per-use |
| Database (MongoDB) | $57-200 | Shared tier sufficient initially |
| CDN/Bandwidth | $0 | Included in Vercel |
| Monitoring (Sentry) | $0-25 | Free tier sufficient |
| **Total** | **$70-300/mo** | |

**Cost-saving strategies**:
- Use free tiers during MVP phase
- Auto-scale down during off-peak hours
- Compress database backups
- Cache aggressively on frontend

#### 8. Security Considerations

- **Secrets Management**: GitHub Secrets (encrypted)
- **API Keys**: Rotated every 90 days
- **CORS**: Restricted to known domains
- **Rate Limiting**: 100 req/min per IP (API Gateway)
- **DDOS Protection**: Cloudflare (optional, $20/mo)
- **SSL/TLS**: Automatic renewal via Let's Encrypt

#### 9. Disaster Recovery

| Scenario | RTO | RPO | Strategy |
|---|---|---|---|
| Frontend outage | 5 min | 0 min | Vercel auto-failover |
| API service down | 15 min | 5 min | Fargate restart + health checks |
| Database corruption | 1 hour | 1 day | MongoDB PITR (point-in-time recovery) |
| Data loss | 24 hours | Daily | Encrypted backups in separate AWS account |

## Alternatives

1. **Self-Hosted (VPS)**
   - Lower ongoing costs; higher operational overhead
   - Rejected: team lacks ops expertise at MVP stage

2. **AWS-Only Stack (Lambda + RDS + S3)**
   - More vendor lock-in; steeper learning curve
   - Rejected: Vercel reduces friction for full-stack team

3. **Heroku (Classic PaaS)**
   - Simpler but deprecated Dynos pricing model
   - Rejected: cost-prohibitive ($50+ minimum)

## Consequences

✅ **Positive**:
- Git-driven deployments (rapid iteration)
- Automatic scaling handles traffic spikes
- Managed backups and disaster recovery
- Clear separation of dev/staging/production
- Monitoring alerts catch issues early
- Predictable monthly costs

⚠️ **Negative**:
- Vendor lock-in (Vercel + MongoDB Atlas)
- Cold starts on serverless (mitigated with warming)
- Limited control over infrastructure (trade-off for simplicity)
- MongoDB Atlas cost grows with data size

🔧 **Mitigations**:
- Document infrastructure setup for reproducibility
- Implement infrastructure-as-code (Terraform for DB config)
- Regular cost audits and optimization
- Migration plan to self-hosted if needed in future
